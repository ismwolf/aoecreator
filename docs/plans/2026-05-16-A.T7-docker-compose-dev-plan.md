## Goals

- Ship `infra/docker-compose.dev.yml` providing Postgres + Redis as the local dev data layer for `apps/web` and `apps/api` (which continue running on the host via `pnpm dev` / `uv run uvicorn` — **hybrid dev**, no app containerization in this task).
- Use `supabase/postgres:<pinned>` as the Postgres image for **maximum prod parity** (pgvector, pgsodium, pg_cron, all extensions Supabase Cloud ships). User decision: heavy (~1GB) image is acceptable cost for parity with Faz 2 B / Faz 3 C / Faz 4 D workloads that exercise pgvector + sodium.
- Use `redis:7-alpine` as the Redis image (small, current LTS; sufficient for Celery broker + cache + rate-limit lock per master plan §3 topology).
- Persist data via **bind mounts** under `./.docker-data/postgres/` and `./.docker-data/redis/` (relative paths from `infra/docker-compose.dev.yml` → `../.docker-data/...`). Easy backup, easy reset (`rm -rf .docker-data/`), easy inspection. `.docker-data/` is `.gitignored`.
- Ship `infra/README.md` documenting first-time bring-up, host-side connection (`psql postgresql://postgres:postgres@localhost:5432/postgres`), how to reset, what's exposed, and a clear "DEV ONLY — prod uses Supabase Cloud" banner.
- Ship `infra/postgres/init/` directory as a Faz 2 B drop-in slot (Postgres entrypoint auto-runs `*.sql` on first volume init). Empty today except `.gitkeep` + a `README.md` explaining the contract.
- Ship `infra/.env.example` so devs can copy → `infra/.env` and override compose-time vars (`POSTGRES_PASSWORD`, etc.) without editing the compose file. Compose uses `${VAR:-default}` so a missing `.env` still produces a working setup.
- Extend `apps/api/.env.example` with **commented placeholder** values for `DATABASE_URL` and `REDIS_URL` so the next dev who reads it knows where compose will be reachable. Do NOT wire these into `aeogen.settings.Settings` — A.T9 owns env-schema expansion.
- Add a single line to `apps/web/.env.example` (or create one if absent — verify in T7.1) describing the same connection string targets, **commented out** because Next.js does not consume `DATABASE_URL` directly (Supabase JS SDK handles that in A.T8). This is purely documentation.
- Add `.docker-data/` and `infra/.env` to repo-root `.gitignore`.
- Verify: `docker compose -f infra/docker-compose.dev.yml up -d` brings both services to `healthy` within 30s; `docker compose exec postgres psql -U postgres -d postgres -c "select version()"` returns a Postgres 15.x version string; `docker compose exec redis redis-cli ping` returns `PONG`; `docker compose down` (without `-v`) leaves `.docker-data/` intact; second `up -d` recovers identical data; final `docker compose down` cleans up containers (but volumes persist).
- No regressions: `apps/web`, `apps/api`, `packages/shared` existing gates all still pass.

### T7.2 — `infra/docker-compose.dev.yml` core (~5 min)

**File created:** `infra/docker-compose.dev.yml`

```yaml
# infra/docker-compose.dev.yml
# Local development data layer — DEV ONLY.
# Production uses Supabase Cloud + managed Redis (Faz 8). See
# infra/docker-compose.prod.yml (Faz 8) for the production blueprint.
#
# Brought up by `docker compose -f infra/docker-compose.dev.yml up -d`
# from the repo root.

name: aeogen

services:
  postgres:
    image: supabase/postgres:15.8.1.060
    container_name: aeogen-postgres
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-postgres}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-postgres}
      POSTGRES_DB: ${POSTGRES_DB:-postgres}
      POSTGRES_HOST_AUTH_METHOD: scram-sha-256
      POSTGRES_INITDB_ARGS: '--auth-host=scram-sha-256'
    ports:
      - '${POSTGRES_PORT:-5432}:5432'
    volumes:
      - ../.docker-data/postgres:/var/lib/postgresql/data
      - ./postgres/init:/docker-entrypoint-initdb.d:ro
    healthcheck:
      test:
        [
          'CMD-SHELL',
          'pg_isready -U ${POSTGRES_USER:-postgres} -d ${POSTGRES_DB:-postgres}',
        ]
      interval: 5s
      timeout: 3s
      retries: 10
      start_period: 15s
    networks:
      - aeogen_dev

  redis:
    image: redis:7-alpine
    container_name: aeogen-redis
    restart: unless-stopped
    ports:
      - '${REDIS_PORT:-6379}:6379'
    volumes:
      - ../.docker-data/redis:/data
    command: ['redis-server', '--appendonly', 'yes', '--save', '60', '1000']
    healthcheck:
      test: ['CMD', 'redis-cli', 'ping']
      interval: 5s
      timeout: 3s
      retries: 10
      start_period: 5s
    networks:
      - aeogen_dev

networks:
  aeogen_dev:
    name: aeogen_dev
    driver: bridge
```

**Design rationale (baked in):**

- No `version:` — Compose v2 deprecation hygiene.
- `name: aeogen` top-level → predictable `aeogen-postgres` / `aeogen-redis` names without `--project-name` flag.
- `${VAR:-default}` for every overridable value → compose works zero-config AND honors override when `infra/.env` exists.
- `scram-sha-256` auth → trains good security habits, even in dev.
- Bind mounts via `../.docker-data/...` → relative to compose file dir (`infra/`), resolves to `<repo>/.docker-data/...`.
- `./postgres/init:/docker-entrypoint-initdb.d:ro` → Postgres entrypoint convention, empty today.
- Redis AOF + RDB → durable enough for dev.
- `start_period: 15s` on Postgres → first-boot init scripts time.

**`infra/.gitkeep`** deleted in this task.

**Verification:**

```powershell
docker compose -f infra/docker-compose.dev.yml config
```

Expected: prints normalized YAML, exits 0, no warnings.

### T7.5 — Smoke-test script (~4 min)

**File created:** `infra/scripts/smoke-test.ps1`

```powershell
#requires -Version 7.0
<#
.SYNOPSIS
  Brings up infra/docker-compose.dev.yml, waits for both services to be
  healthy, runs basic connectivity checks via container exec, prints
  success, and (by default) leaves the stack running.

.EXAMPLE
  pwsh infra/scripts/smoke-test.ps1
  pwsh infra/scripts/smoke-test.ps1 -TearDown
  pwsh infra/scripts/smoke-test.ps1 -TearDown -Wipe
#>
[CmdletBinding()]
param(
  [switch]$TearDown,
  [switch]$Wipe
)

$ErrorActionPreference = "Stop"
$composeFile = "infra/docker-compose.dev.yml"

function Wait-Healthy {
  param([string]$service, [int]$timeoutSec = 60)
  $deadline = (Get-Date).AddSeconds($timeoutSec)
  while ((Get-Date) -lt $deadline) {
    $json = docker compose -f $composeFile ps --format json $service
    if ($json) {
      $status = ($json | ConvertFrom-Json).Health
      if ($status -eq "healthy") { return }
    }
    Start-Sleep -Seconds 2
  }
  throw "service '$service' did not become healthy within ${timeoutSec}s"
}

Write-Host "=== bring up ==="
docker compose -f $composeFile up -d
if ($LASTEXITCODE -ne 0) { throw "docker compose up failed" }

Write-Host "=== wait healthy ==="
Wait-Healthy -service postgres
Wait-Healthy -service redis

Write-Host "=== postgres connectivity ==="
docker compose -f $composeFile exec -T postgres pg_isready -U postgres -d postgres
docker compose -f $composeFile exec -T postgres psql -U postgres -d postgres -c "select version();"

Write-Host "=== redis connectivity ==="
docker compose -f $composeFile exec -T redis redis-cli ping

Write-Host "=== persistence check (write key, restart, read) ==="
docker compose -f $composeFile exec -T redis redis-cli set aeogen:smoke ok | Out-Null
docker compose -f $composeFile restart redis | Out-Null
Wait-Healthy -service redis -timeoutSec 30
$got = docker compose -f $composeFile exec -T redis redis-cli get aeogen:smoke
if ($got.Trim() -ne "ok") { throw "redis did not persist 'aeogen:smoke' across restart (got: '$got')" }
docker compose -f $composeFile exec -T redis redis-cli del aeogen:smoke | Out-Null

Write-Host "=== smoke OK ==="

if ($TearDown) {
  Write-Host "=== tear down ==="
  docker compose -f $composeFile down
  if ($Wipe) {
    Write-Host "=== wipe .docker-data/ ==="
    if (Test-Path .docker-data) { Remove-Item -Recurse -Force .docker-data }
  }
}
```

## Risks

- **Postgres tag drift:** `supabase/postgres:15.8.1.060` may not exist when implementer runs `docker pull`. Mitigation: T7.1 verifies before commit; substitute latest `15.8.1.x` if missing.
- **Disk usage:** supabase/postgres ~1GB. Mitigation: README documents; user explicitly chose Supabase parity.
- **Bind mount perf on Win/Mac:** Docker Desktop FS virtualization slower than native. Acceptable for dev.
- **`scram-sha-256` vs `trust` surprise:** Devs may expect passwordless local. README documents connection string.
- **Port collisions:** 5432 / 6379 may be in use. Mitigation: `infra/.env` override.
- **First-boot init script confusion:** Postgres only runs init scripts on FIRST volume init. README documents.
- **`docker compose ps --format json` schema:** `.Health` field present in Compose 2.20+. Document "Docker Desktop ≥ 4.30" requirement.
- **PowerShell-only smoke script:** PowerShell Core (`pwsh`) is cross-platform. Bash mirror can land in A.T12.
- **Volume init race on slow disks:** If first-boot init exceeds 15s `start_period`, bump to 30s.
- **`docker compose exec -T` flag:** `-T` disables TTY, required for non-interactive scripts. Every exec uses it.
- **Apple Silicon `exec format error`:** Multi-arch supported as of 2024+; `platform: linux/amd64` fallback documented in README.

# A.T10 + A.T11 + A.T13 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add full pre-commit enforcement (prettier + ESLint + ruff + commitlint + gitleaks) and a root README.

**Architecture:** Single root-level husky install manages three hooks (pre-commit, commit-msg, pre-push). lint-staged runs formatters/linters only on staged files. commitlint validates Conventional Commits. gitleaks scans for secrets. All checks mirrored in CI. README documents the monorepo for new contributors.

**Tech Stack:** husky v9, lint-staged, prettier + prettier-plugin-tailwindcss ^0.7.4, eslint-config-prettier, @commitlint/cli + @commitlint/config-conventional, gitleaks (system binary, graceful skip if absent), GitHub Actions.

## Task 4: lint-staged config

**Files:**

- Create: `lint-staged.config.mjs`

- [ ] **Step 4.1: Create `lint-staged.config.mjs` at repo root**

```js
export default {
  '*.{ts,tsx,js,mjs,cjs}': ['prettier --write', 'eslint --fix'],
  '*.{json,md,yml,yaml}': ['prettier --write'],
  'apps/api/**/*.py': (files) => [
    `uv run --directory apps/api ruff check --fix ${files.join(' ')}`,
    `uv run --directory apps/api ruff format ${files.join(' ')}`,
  ],
};
```

Notes:

- `prettier --write` runs before `eslint --fix` so ESLint sees already-formatted code.
- Python glob is scoped to `apps/api/` to avoid matching any future Python scripts elsewhere.
- `uv run --directory apps/api` ensures the correct virtualenv and `pyproject.toml` context is used regardless of the current working directory.

- [ ] **Step 4.2: Smoke-test lint-staged with a dry run**


Expected: Output lists which commands would run per file type. No errors.

## Task 7: gitleaks — A.T11

**Files:**

- Create: `.gitleaks.toml`
- Modify: `.husky/pre-commit` (append gitleaks call)

- [ ] **Step 7.1: Create `.gitleaks.toml`**

```toml
title = "aeogenerator gitleaks config"

[extend]
# Use gitleaks default ruleset as base
useDefault = true

[allowlist]
description = "Test fixtures, example keys, placeholders"
regexes = [
  # Supabase placeholder keys used in CI env and .env.example files
  '''sb_publishable_placeholder_''',
  '''sb_secret_placeholder_''',
  # pytest / .env.example dummy values
  '''placeholder''',
]
paths = [
  # Example env files are safe by definition
  '''.env.example''',
  '''.env.test''',
  # Lock files contain hashes that pattern-match as secrets
  '''pnpm-lock\.yaml''',
  '''uv\.lock''',
  # Generated Supabase types — no secrets, only schema
  '''apps/web/src/lib/database\.types\.ts''',
]
```

- [ ] **Step 7.2: Update `.husky/pre-commit` to include gitleaks**

Replace with:

```sh
pnpm lint-staged

if command -v gitleaks >/dev/null 2>&1; then
  gitleaks protect --staged --config .gitleaks.toml -v
else
  echo "⚠️  gitleaks not found — secret scanning skipped locally."
  echo "   Install: https://github.com/gitleaks/gitleaks#installing"
  echo "   CI will still catch secrets before merge."
fi
```

- [ ] **Step 7.3: Verify gitleaks config parses (if gitleaks is installed)**

The final order in `node-checks` should be:

1. Checkout
2. Install pnpm
3. Setup Node.js
4. Install dependencies
5. Typecheck (workspace)
6. **Lint (workspace)**
7. **Format check (prettier)** ← new
8. Build (workspace)
9. Test (workspace)

- [ ] **Step 8.2: Add gitleaks scan job to CI**

Append a new job at the end of `.github/workflows/ci.yml` (after `python-checks`):

```yaml
gitleaks:
  name: Secret scan (gitleaks)
  runs-on: ubuntu-latest
  timeout-minutes: 5
  steps:
    - name: Checkout
      uses: actions/checkout@v4
      with:
        fetch-depth: 0

    - name: Run gitleaks
      uses: gitleaks/gitleaks-action@v2
      env:
        GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        GITLEAKS_CONFIG: .gitleaks.toml
```

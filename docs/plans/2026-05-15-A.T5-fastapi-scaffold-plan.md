- Wire **ruff** (lint + format), **mypy strict**, **pytest + pytest-asyncio** with PEP 621 metadata in a single `pyproject.toml`.
- Ship `aeogen.main:create_app()` factory + module-level `app = create_app()` exposing `GET /health/live` and `GET /health/ready` per master plan §4.H (operational baseline) and global CLAUDE.md security rules.
- Ship `aeogen.settings.Settings` (pydantic-settings BaseSettings) as the FastAPI parity for `@t3-oss/env-nextjs` in apps/web — Supabase / OpenRouter / DB / Redis fields are deferred to A.T8/T9 (mirrors A.T4's deferral of Supabase env to A.T8).
- Ship one pytest-asyncio integration test that constructs the app via the factory and asserts `GET /health/live` returns `200` + `{"status": "alive", ...}` — proves the wiring end-to-end.
- Verify: `uv sync` resolves, `uv run ruff check`, `uv run ruff format --check`, `uv run mypy src`, `uv run pytest` all pass. `uv run uvicorn aeogen.main:app --reload` boots and serves `/health/live`.

### T5.4 — `aeogen.settings` (pydantic-settings parity for t3-env) (~5 min)
**File created:** `apps/api/src/aeogen/settings.py`

**Contents sketch (Pydantic v2 + pydantic-settings v2):**
```python
"""Settings parity for apps/web's @t3-oss/env-nextjs.

Validates env vars at startup. Like A.T4's src/lib/env.ts, this only
declares fields that exist today — Supabase / OpenRouter / DB fields
are added in A.T8/T9 alongside their first real consumers.
"""
from functools import lru_cache
from typing import Literal

from pydantic import Field
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    """Top-level application settings. Loaded from env + .env.local."""

    model_config = SettingsConfigDict(
        env_file=(".env", ".env.local"),
        env_file_encoding="utf-8",
        case_sensitive=False,
        extra="ignore",
    )

    app_env: Literal["development", "test", "staging", "production"] = Field(
        default="development",
        description="Deployment environment.",
    )
    app_name: str = Field(default="aeogen-api")
    app_version: str = Field(default="0.0.0")
    log_level: Literal["DEBUG", "INFO", "WARNING", "ERROR"] = Field(default="INFO")

    # Server
    host: str = Field(default="127.0.0.1")
    port: int = Field(default=8000, ge=1, le=65535)


@lru_cache(maxsize=1)
def get_settings() -> Settings:
    """Cached settings accessor for DI use."""
    return Settings()
```

### T5.5 — `aeogen.main:create_app` + health endpoints (~5 min)
**File created:** `apps/api/src/aeogen/main.py`

**Contents sketch:**
```python
"""FastAPI app factory + health endpoints.

Module-level `app = create_app()` so `uvicorn aeogen.main:app` works
out of the box. Tests construct fresh instances via `create_app()`.
"""
from datetime import UTC, datetime
from typing import Any

from fastapi import FastAPI

from aeogen import __version__
from aeogen.settings import get_settings

_STARTUP_TIME = datetime.now(UTC)


def create_app() -> FastAPI:
    """Construct a fresh FastAPI application instance.

    Factory pattern enables test isolation — each test can build its own
    app without the module-level singleton leaking state.
    """
    settings = get_settings()
    app = FastAPI(
        title=settings.app_name,
        version=settings.app_version or __version__,
        docs_url="/docs" if settings.app_env != "production" else None,
        redoc_url=None,
    )

    @app.get("/health/live", tags=["health"])
    async def health_live() -> dict[str, Any]:
        """Liveness probe — process is up and the event loop is responsive."""
        return {
            "status": "alive",
            "version": settings.app_version or __version__,
            "timestamp": datetime.now(UTC).isoformat(),
            "uptime_seconds": (datetime.now(UTC) - _STARTUP_TIME).total_seconds(),
        }

    @app.get("/health/ready", tags=["health"])
    async def health_ready() -> dict[str, Any]:
        """Readiness probe — all required dependencies are reachable.

        Scaffold version: no deps yet, so this always reports ready with
        an empty checks map. A.T7+ will add DB + Redis checks.
        """
        return {
            "status": "ready",
            "version": settings.app_version or __version__,
            "timestamp": datetime.now(UTC).isoformat(),
            "checks": {},
        }

    return app


app = create_app()
```

## Risks

- **uv resolver vs system Python mismatch:** If the developer has Python 3.13 system-wide and no 3.12 installed, `uv sync` can still succeed by downloading 3.12 — but only if `uv python install 3.12` was run, or `[tool.uv]` settings allow it. Mitigation: `.python-version` pins 3.12 and README documents `uv python pin 3.12` / `uv python install 3.12`.
- **`ANN` rule noise:** ruff's `ANN` (flake8-annotations) is strict. With mypy strict already running, some `ANN` errors are redundant. Mitigation: `ANN101` / `ANN102` ignored (deprecated rules anyway); per-file ignore on tests. If `ANN401` (dynamic `Any`) becomes painful in health endpoints (returning `dict[str, Any]`), add it to ignores — flagged as a sub-decision the implementer can make without escalation.
- **`pytest-asyncio` mode conflicts:** Setting `asyncio_mode = "auto"` means EVERY async test is treated as async without a decorator. If a future test author writes a sync test that imports `asyncio` accidentally, behavior could surprise. Mitigation: documented in README + tests/conftest comment; deferred upgrade path is `strict` mode once the test base grows.
- **Hatchling + src-layout:** Some teams hit "package not found" errors when hatchling can't infer the src layout. Mitigation: explicit `[tool.hatch.build.targets.wheel] packages = ["src/aeogen"]`. Detection: `uv sync` would fail with `ModuleNotFoundError: aeogen`.
- **`pydantic-settings` `.env` file precedence:** Multiple `.env` files (`.env`, `.env.local`) load in declared order with LATER files OVERRIDING earlier — mirrors Next.js. Confusion risk if a developer expects `.env.local` to be overridden by `.env`. Mitigation: README documents the order explicitly.
- **Windows + uvicorn `--reload` watchdog:** Some versions of uvicorn's `[standard]` extras include `watchfiles` which has Windows file-lock quirks. Mitigation: use the default reloader; if a test machine misbehaves, drop `--reload` and use `--workers 1`.
- **`uvicorn[standard]` includes `httptools` / `uvloop`:** `uvloop` does NOT build on Windows. `uvicorn[standard]` skips it on Windows automatically — but if a developer is on WSL2 it tries to install. Mitigation: documented + accept that Windows-native runs use the slower asyncio loop. (Production on Linux KVM2 will get uvloop.)
- **Root `pnpm -r` confusion:** A developer running `pnpm -r test` from the repo root will NOT run apps/api tests — they will only hit Node packages. Mitigation: README has a "Why this is NOT in the pnpm workspace" section; orchestrator's PROGRESS.md update should reference this explicitly.
- **Test isolation via module-level `app`:** Module-level `app = create_app()` is convenient for `uvicorn aeogen.main:app` but tests should use `create_app()` directly. If a future test reuses the module-level singleton with custom DI overrides, state leaks. Mitigation: `conftest.py` fixture always uses `create_app()`. Documented.
- **`uv.lock` cross-platform stability:** uv lockfiles are platform-portable but include marker metadata. Lockfile may show large diffs when developers run on different OSes. Mitigation: commit the lockfile and document `uv lock --check` as the verification (NOT `uv lock`, which rewrites).

## Open questions

1. **`black` vs `ruff format`** — Master plan §4.A and PROGRESS.md A.T5 line both say "ruff, black, mypy". As of 2025 onward, `ruff format` (same engine, ~30x faster, single tool) has effectively superseded `black` for new Python projects — Astral made format compat with black 24.x. **Recommendation:** drop `black`, use `ruff format` only. This is reflected in the plan above. **Flag for user:** if you specifically want `black` retained (e.g., to match a future contributor's editor setup or for `pre-commit` ecosystem reasons), add `black>=24.0` to `[project.optional-dependencies.dev]` and a `[tool.black]` section.

2. **`pre-commit-hooks` config now or defer to A.T10/T11?** — A.T10 plans Husky/commitlint/lint-staged for the Node side. The Python side typically uses `pre-commit` (the Python tool, not Husky) with `.pre-commit-config.yaml`. **Recommendation:** defer to A.T10/T11 so both sides ship together with a single PR. Adding it here splits the cross-cutting concern. **Flag for user:** if you want the Python pre-commit hooks today, add a `.pre-commit-config.yaml` in `apps/api/` (or repo root) with ruff + mypy entries — but this duplicates effort with A.T10.

3. **Module-level `app = create_app()` or factory-only?** — Recommendation: keep BOTH. The module-level `app` makes `uvicorn aeogen.main:app` work without users needing `--factory` flag. The factory is for tests. The trade-off is that `create_app()` runs once at import time (reads env, builds settings), which means import-time side effects. For a backend scaffold this is normal and matches the Next.js parity in apps/web. **Flag for user:** if you want pure factory + `uvicorn --factory aeogen.main:create_app`, drop the module-level line.

4. **Monorepo invocation strategy — three options:**
   - **A. Root `package.json` shells into apps/api:**
     ```json
     "api:lint": "uv --project apps/api run ruff check apps/api",
     "api:typecheck": "uv --project apps/api run mypy apps/api/src",
     "api:test": "uv --project apps/api run pytest apps/api/tests",
     "api:dev": "uv --project apps/api run uvicorn aeogen.main:app --reload"
     ```
     Pro: single mental model — `pnpm api:test` works from root. Con: mixes Node package.json with Python — feels off.
   - **B. README documentation only — `cd apps/api && uv run ...`:**
     Pro: zero cross-tool coupling, cleanest separation. Con: developers must remember to `cd`.
   - **C. Root `Makefile` or `taskfile.yml`:**
     Pro: language-agnostic task runner, also helps for future Docker / Supabase commands. Con: Windows developers need `make` from chocolatey or `task` from scoop — extra setup friction.
   - **Recommendation: B** for A.T5 (least invasive, matches the "apps/api is intentionally outside the pnpm workspace" decision). Revisit C in A.T7 when docker-compose + supabase CLI also need a unified entry point. **Flag for user:** pick A, B, or C.

5. **License field in `pyproject.toml`** — Master plan does not specify a project license. Above uses `license = { text = "UNLICENSED" }` (PEP 639-friendly, says "all rights reserved" without ambiguity). Alternatives: `MIT`, `Apache-2.0`, `Proprietary`. **Flag for user:** confirm license choice — applies to apps/web too if you want full repo parity.

6. **CORS placeholder middleware?** — apps/web will eventually call `apps/api` via `fetch`. We have NOT added `CORSMiddleware` in the scaffold because origin allow-lists depend on Supabase + Next.js deployment URLs (deferred to A.T8). **Flag for user:** confirm deferral to A.T8 is acceptable; if you want a permissive dev-only CORS (`*`) wired today, it is a 4-line addition to `create_app()`.

7. **`pydantic-settings` `.env.local` parity vs Next.js semantics** — Next.js loads `.env.local` AFTER `.env` (so `.env.local` wins). pydantic-settings honors the order in `env_file=(...)` — LATER files OVERRIDE earlier. Above declares `env_file=(".env", ".env.local")` to match Next.js. **Flag for user:** confirm parity is intended (it is the safe default).

## Cross-platform notes
- All commands above are PowerShell-compatible. `uv`, `curl.exe`, `git` are the only externals.
- `Start-Process` / `Stop-Process` used in place of bash `&` for backgrounding uvicorn. Skip the live curl check if backgrounding is awkward and rely on T5.6's pytest, which exercises the same code path via ASGI transport.
- No POSIX-only tools. `uvloop` skipped on Windows automatically by `uvicorn[standard]`.
- Line endings: rely on `.gitattributes` (added in A.T2 if present) or accept CRLF locally — ruff and pytest are agnostic.

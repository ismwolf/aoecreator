# A.T4 — apps/web Next.js 15 Scaffold Plan
Date: 2026-05-14

Predecessors: A.T3 ✅ (pnpm workspace skeleton)
Successors: A.T6 (packages/shared zod schemas), A.T8 (supabase + types), A.T9 (env validation expansion)

## Goals
- Stand up `apps/web/` as a Next.js 15.5.9+ workspace package named `@aeogen/web`, App Router, RSC default, TS strict, Tailwind, shadcn/ui baseline.
- Wire the workspace fan-out scripts (`lint`, `typecheck`, `test`, `build`, `dev`) so root `pnpm -r` calls succeed.
- Land `(marketing) / (auth) / (app)` route group skeletons (empty `layout.tsx` + `page.tsx` each).
- Ship a minimal `src/lib/env.ts` via `@t3-oss/env-nextjs` + Zod with `NEXT_PUBLIC_APP_URL` only — Supabase vars are deferred to A.T8.
- Configure security response headers in `next.config.ts` (HSTS, X-Content-Type-Options, Referrer-Policy, X-Frame-Options, baseline CSP placeholder).
- Verify: `pnpm install`, root `pnpm -r typecheck`, and `pnpm --filter @aeogen/web dev` serving on port 3000.

## Non-goals
- No Supabase client (`@supabase/ssr`) wiring — deferred to A.T8.
- No shadcn components beyond the CLI baseline init (`components.json`, `lib/utils.ts`, base CSS variables). No Button/Card/etc. yet.
- No Vitest test files. Optional: drop a `vitest.config.ts` stub so the workspace `test` script does not error — flagged in Open questions.
- No real CSP lockdown — only a permissive placeholder header documenting that A.T8+ will tighten it once Supabase + OpenRouter origins are known.
- No Husky/lint-staged/gitleaks/CI — those are A.T10–T12.

### T4.5 — App Router skeleton + 3 route groups (~4 min)
**Files created:**
- `apps/web/src/app/layout.tsx` — root layout. RSC. Imports `./globals.css`, sets `<html lang="tr">`, renders `{children}` inside `<body>`. Exports `metadata = { title: "aeogenerator", description: "AEO/GEO multi-agent SaaS" }`.
- `apps/web/src/app/page.tsx` — root route. Returns a minimal "aeogenerator — scaffold OK" RSC. Do NOT use `"use client"`.
- `apps/web/src/app/(marketing)/layout.tsx` — passthrough RSC layout returning `{children}`.
- `apps/web/src/app/(marketing)/page.tsx` — placeholder "marketing".
- `apps/web/src/app/(auth)/layout.tsx` — passthrough.
- `apps/web/src/app/(auth)/page.tsx` — placeholder "auth".
- `apps/web/src/app/(app)/layout.tsx` — passthrough.
- `apps/web/src/app/(app)/page.tsx` — placeholder "app".

**Note on collision:** Next.js will fail if two route groups expose the same effective path (`/`). Therefore the root `app/page.tsx` AND `(marketing)/page.tsx` both resolving to `/` would conflict. Resolution: keep `(marketing)/page.tsx` as `/` and DELETE the top-level `app/page.tsx`. Or give the groups distinct child segments like `(marketing)/(home)/page.tsx` later. **Decision for T4.5:** drop the root `app/page.tsx` and let `(marketing)/page.tsx` own `/`. `(auth)/page.tsx` and `(app)/page.tsx` likewise conflict at `/` — instead use `(auth)/login/page.tsx` and `(app)/dashboard/page.tsx` placeholders so each group has a non-colliding leaf. (See Open questions for whether to defer all three placeholders.)

**Revised file list (collision-safe):**
- `src/app/layout.tsx` (root layout — RSC, mandatory)
- `src/app/(marketing)/layout.tsx`
- `src/app/(marketing)/page.tsx` (owns `/`)
- `src/app/(auth)/layout.tsx`
- `src/app/(auth)/login/page.tsx` (placeholder text "login")
- `src/app/(app)/layout.tsx`

## Open questions
1. **Tailwind v4 vs v3** — Master plan §2 only locks "Tailwind". v4 (Jan 2025 GA) is CSS-first, no `tailwind.config.ts`, faster, but younger. v3 is battle-tested with broader plugin ecosystem. shadcn/ui supports both (v4 since shadcn `2.1.0`). **Recommendation:** v4 for the modern bet, fall back to v3 if shadcn init throws. Flag for user.
2. **Vitest config stub now or later?** Plan currently uses a placeholder `test` script that exits 0. Alternative: drop a `vitest.config.ts` + `@vitest/coverage-v8` dev-dep now, run `vitest --run --passWithNoTests` so the slot is real. Adds ~30 sec but removes a future migration. Flag for user.
3. **Root `app/page.tsx` collision resolution** — I resolved by deleting the root `app/page.tsx` and letting `(marketing)/page.tsx` own `/`. Alternatives: keep root page and put marketing under `(marketing)/home/page.tsx` with redirect. Either is valid; current choice aligns with master plan §4.F routes.
4. **`(auth)/page.tsx` and `(app)/page.tsx` route collision** — Resolved by promoting them to `(auth)/login/page.tsx` and `(app)/dashboard/page.tsx` placeholders since those are the actual v1 routes per master plan §4.F. Alternative: defer and create only `(marketing)` group in T4. Current choice keeps task list short and matches §4.F.
5. **CSP placeholder strictness** — Current CSP allows `'unsafe-inline'` and `'unsafe-eval'` for scripts because Next dev mode needs them. Production should use nonces (Next 15.5 supports `headers()` + middleware nonce injection). Deferred to A.T8 once Supabase + OpenRouter origins are known. Flag for user.
6. **Turbopack flag** — `next dev --turbopack` is GA in Next 15.5+. Keeping it on. Alternative: stay on Webpack for dev to match prod. Flag if user prefers Webpack.
7. **`typedRoutes` experimental** — Currently enabled in `next.config.ts`. It is still flagged `experimental` in 15.5 (now stable but still under flag). Drop if it causes friction with route groups.

## Risks
- **`create-next-app` pollution:** Mitigated by manual scaffold (T4.1). Risk: more surface for typos in `package.json` / `tsconfig.json`. Mitigation: copy known-good values from Next 15.5 docs and verify with `typecheck` + `build`.
- **Tailwind v4 + shadcn CLI mismatch:** shadcn `init` historically wrote `tailwind.config.ts` and `globals.css` `@tailwind` directives. Recent shadcn versions support v4's `@import "tailwindcss"` form. If the CLI generates v3-style artifacts on a v4 install, T4.4 will need a v3 fallback. **Detection:** after T4.4 if `globals.css` has `@tailwind base; @tailwind components; @tailwind utilities;` we are on v3 path — adjust deps + postcss.config accordingly.
- **shadcn CLI requires interactive TTY:** `pnpm dlx shadcn@latest init --yes` may still prompt for base-color / CSS-variables in some versions. Fallback: pass `--defaults` or run interactively once and commit the artifacts.
- **pnpm workspace resolution:** Already verified by A.T3 that `apps/web` is in `pnpm-workspace.yaml`. Risk: `pnpm install` could fail if a transitive peer demands a different React 18. Mitigation: pin `react@^19.2.0` and let pnpm's strict peer resolver report. Add `.npmrc` with `auto-install-peers=true` only if needed.
- **Windows path / line-ending quirks:** `pnpm` and `next` both tolerate Windows paths. ESLint flat config + `eslint-config-next` requires `@eslint/eslintrc` `FlatCompat` shim — this is documented; do not skip.
- **`next-env.d.ts` regeneration:** `next dev` rewrites this file. If committed, expect a churn diff on first dev run. Acceptable; per Next docs commit the stub.
- **Port 3000 conflict:** Plan execution may hit a busy port. Mitigation: `next dev -p 3000` will fail loudly; switch to 3001 if needed and note in PROGRESS.md.

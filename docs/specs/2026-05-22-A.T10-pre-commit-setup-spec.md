# Spec: A.T10 — Pre-commit Setup (Husky + commitlint + lint-staged + prettier)

**Date:** 2026-05-22
**Slug:** A.T10-pre-commit-setup
**Status:** Approved

---

## Problem

The repository has CI checks (node-checks + python-checks) but no local pre-commit enforcement.
Developers can commit malformatted code, non-conventional commit messages, or code that fails
linting — these are only caught after push, slowing the feedback loop.

## Goals

- Enforce Conventional Commits format on every local commit
- Auto-fix and format TS/JS/JSON/MD/YAML files before commit via prettier + ESLint
- Auto-fix and format Python files before commit via ruff
- Sort Tailwind CSS class names automatically (prettier-plugin-tailwindcss)
- Block push if typecheck or tests fail
- Mirror prettier format check in CI (no format divergence between local and remote)

## Non-Goals

- Python type-checking (mypy) in pre-commit — too slow; CI only
- Full test suite in pre-commit — too slow; pre-push only
- Replacing ESLint with prettier for logic/style rules — they are complementary

## Tech stack additions

| Package                           | Scope                             | Purpose                                             |
| --------------------------------- | --------------------------------- | --------------------------------------------------- |
| `husky`                           | root devDep                       | Git hook manager (v9, install via `prepare` script) |
| `lint-staged`                     | root devDep                       | Run linters only on staged files                    |
| `@commitlint/cli`                 | root devDep                       | Validate commit messages                            |
| `@commitlint/config-conventional` | root devDep                       | Conventional Commits ruleset                        |
| `prettier`                        | root devDep                       | Formatter for TS/JS/JSON/MD/YAML                    |
| `prettier-plugin-tailwindcss`     | root devDep                       | Auto-sort Tailwind class names                      |
| `eslint-config-prettier`          | apps/web + packages/shared devDep | Disable ESLint rules that conflict with prettier    |

## Approach

### 1. Prettier (root-level, workspace-wide)

Single `.prettierrc.json` at repo root applies to all TS/JS/JSON/MD/YAML files.

```json
{
  "singleQuote": true,
  "semi": true,
  "tabWidth": 2,
  "trailingComma": "es5",
  "plugins": ["prettier-plugin-tailwindcss"]
}
```

`.prettierignore` excludes:

- Build outputs: `.next/`, `dist/`, `out/`
- Lock files: `pnpm-lock.yaml`, `uv.lock`
- Generated files: `apps/web/src/lib/database.types.ts`, `packages/shared/python/`
- Python source (ruff owns formatting): `*.py`

### 2. ESLint ↔ prettier integration

`eslint-config-prettier` added as last item in the `extends`/`plugins` array of:

- `apps/web/eslint.config.mjs`
- `packages/shared/eslint.config.mjs`

This turns off all ESLint formatting rules so prettier is the single source of truth for style.

### 3. lint-staged (root `lint-staged.config.mjs`)

```js
export default {
  '*.{ts,tsx,js,mjs,cjs}': ['prettier --write', 'eslint --fix'],
  '*.{json,md,yml,yaml}': ['prettier --write'],
  'apps/api/**/*.py': (files) => [
    `uv run --directory apps/api ruff check --fix ${files.join(' ')}`,
    `uv run --directory apps/api ruff format ${files.join(' ')}`,
  ],
};
```

Notes:

- `prettier --write` runs before `eslint --fix` so ESLint sees already-formatted code
- Python glob uses directory prefix to scope to `apps/api/` only
- `uv run --directory apps/api` ensures correct virtualenv + pyproject.toml context

### 4. commitlint (root `commitlint.config.mjs`)

```js
export default { extends: ['@commitlint/config-conventional'] };
```

Enforces: `<type>[(scope)][!]: <description>` — types: feat, fix, build, chore, ci, docs,
perf, refactor, revert, style, test. Max subject length: 100 chars.

### 5. Husky hooks

| File                | Content                             |
| ------------------- | ----------------------------------- |
| `.husky/pre-commit` | `pnpm lint-staged`                  |
| `.husky/commit-msg` | `pnpm commitlint --edit "$1"`       |
| `.husky/pre-push`   | `pnpm -r typecheck && pnpm -r test` |

`package.json` gets `"prepare": "husky"` script so hooks install automatically on `pnpm install`.

### 6. CI update

`.github/workflows/ci.yml` → `node-checks` job gets a new step after `Lint`:

```yaml
- name: Format check (prettier)
  run: pnpm prettier --check .
```

This ensures CI fails if a commit bypasses hooks (e.g., `--no-verify`) with formatting issues.

## Risks

- **Prettier reformats existing files in bulk** — expected on first run; entire codebase gets
  formatted. One large diff commit, then incremental from there.
- **prettier-plugin-tailwindcss version** — must match Tailwind v4 API. Pin to `^0.7.4`
  (v0.7.x is the first series with full Tailwind v4 flat-config support; latest is 0.7.4).
- **pre-push is slow** — typecheck + test on every push. Acceptable for this team size.
  Can be disabled with `--no-verify` in emergency (gitleaks A.T11 will flag this risk).
- **Python files with absolute paths in lint-staged** — ruff accepts absolute paths; tested
  pattern is standard for polyglot monorepos.

## Verification

1. `pnpm install` → husky hooks installed (`.husky/` files executable)
2. `echo "bad commit" | pnpm commitlint` → exits 1
3. `echo "feat: add thing" | pnpm commitlint` → exits 0
4. Stage a `.ts` file with formatting issues → `git commit` auto-fixes + commits
5. Stage a `.py` file with ruff violations → `git commit` auto-fixes + commits
6. `pnpm prettier --check .` → exits 0 (after initial format pass)
7. CI `node-checks` → prettier --check step passes
8. `git push` on a branch with failing typecheck → blocked
